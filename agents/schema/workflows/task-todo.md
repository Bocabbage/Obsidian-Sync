# Task Todo、过程笔记与 Daily 续入

Daily 保留当天安排与原始记录；Task 按 Todo 汇集完整过程。用户可直接在 Task 写，也可在 Daily 随手写后由 review 整理。过程笔记不编号、不建独立页面，不强制拆成待办。

## 四列表格

新建、补录和更新统一使用一张连续的 Todo 表，每个独立事项占一行。

```markdown
## Todo

| 事项 | 状态 | 完成时间 | 备注 |
|---|---|---|---|
| 005 · 代码开发 <!-- task-step {"id":"step-005","created":"2026-10-23","occurred":"2026-10-22"} --> | 进行中 | — | [[workspace/daily/2026/2026-10/2026-10-26.daily\|2026-10-26]]<br>策略有变化，继续记录问题与调整。 |

> [!info]- 历史回链兼容（编号对应表格事项）
>
> 005 ^step-005
```

- 每行固定四列，表内不能插空行。单元格中的竖线用反斜线转义，备注换行写成 `<br>`。内部步骤保留在备注，同一天沿用已有日期入口，日期倒序并保留原顺序与层级。
- 状态使用待办、进行中、已完成、已取消、暂停或已转交。已完成项的完成时间链接当天 Daily 的 `#收尾`，其余留空或写 `—`。取消日期写入元数据的 `closed`。
- `task-step` 注释保存稳定的 `id` 和真实录入日 `created`。历史补录用 `occurred`，最早续入日用 `resume`，显式暂停可用 `paused: true`。保存状态、日期和原有来源链接时沿用同一个 ID。
- 表格下每项保留唯一的 `^step-NNN` 兼容锚点，既有 Daily 回链继续指向同一条事项。校验每项只统计一次。旧列表仍可读取，整理时并入表格并迁移日期、备注和锚点。
- 同时影响多个事项或归属不明的笔记放在可选的 `## 整体思路`，按日期保留来源。


每项 Todo 的过程明细按来源日期和原有层级写入同页的 `## Todo 过程明细`，表格负责汇总。已有过程笔记的事项，将唯一的 `^step-NNN` 放在对应明细块的编号行（例如 `> 015 ^step-015`），让 Daily 的「明细」直接跳到过程记录。表格备注可保留摘要或来源链接。复盘时先核对 Daily 内部步骤已按同一事项归档，再做收口检查。


归档过程明细时，先用当前 Task 路径和 step ID 确认事项身份。只收录该事项下实际缩进的笔记，到下一个同级事项、分组或标题即停止。同级 Checkbox 各自归档，即使标题相似或外部链接相同。已有关联的表格备注也应有独立明细块，保持同一锚点。没有过程内容的事项保留定位锚点即可。收口前逐项核对明细里没有其他事项的记录。

核对过程明细时，逐项对照表格备注和来源 Daily。先确认 Task 路径、step ID 和日期，再比较内容。等义摘要保留一次，摘要省略的步骤、疑问、状态和链接补进对应日期。跨任务移交可以保留明确标注的回链。若原文未带 step，仅在同一 Task 内能唯一对应时归档。手写时让同级事项对齐，笔记比事项多缩进一级。

## Daily Review

1. 阅读当天全部 Task occurrence 和人工笔记，包括内部列表、引用块、材料链接、当天完成与取消项；优先按已有 step、外部问题链接和范围匹配，不能只按标题相似合并。
2. 先更新 Task Todo 的状态与真实日期，再把相关过程归到对应 Todo 的来源日期下。保留用户原话、疑问、判断强度、重复出现的内部步骤和层级，不把局部完成写成整项完成。当天提出并完成的独立事项同样保留。
3. 同一 Todo 同一天只有一个日期入口。重复 review 先比较已有笔记和来源，只补尚未整理的内容；不要重复追加相同来源，也不跨日期去重。用户直接写入 Task 的内容不得覆盖；源文后来纠正时明确追加更正，不静默抹去原判断。
4. Daily 原始笔记保留。只在当前获准复盘的开放 Daily 补精确回链和收口状态；历史或已关闭 Daily 不重开、不补写。当天局部完成可 `[x]` 而 Task Todo 仍进行中；仅取消当天安排不取消整个 Todo。Task 本体结束仍须用户明确确认。
5. 保存前逐项核对：全部人工笔记已归入对应 Todo 或整体思路；每段来源可追溯；原日期、状态、材料链接与原有内容完整；未生成重复日期入口。无新增笔记则跳过笔记整理，不制造每日状态流水账。
6. 先保存 Task，重读核对，再保存当前 Daily 关联，最后运行 `daily-review-check.mjs`。日期不早于 2026-10-14 的开放 Daily，其 Task 子项收口前须有唯一有效同 Task step 链接；这是 Agent 整理后的校验，不是用户手写格式要求。该脚本校验状态与回链，笔记完整性和语义归属由 Agent 逐项核对，不声称脚本验证了笔记内容。

## 晨间自动续入

本地桌面插件 `.obsidian/plugins/vault-daily-todos/` 通过 Vault 的文件创建/修改事件处理核心 Daily Notes 生成的模板，不需要 Templater。实现采用 [Obsidian Vault API 的原子 process](https://docs.obsidian.md/Plugins/Vault) 并校验读取后页面未被改动。

- 只处理 Shanghai 今天、正式路径、`type: daily`、`status: open` 且含 `<!-- task-todo:pending -->` 的页面。成功后替换为一次性生成标记；即使零条也标记完成。不在阅读视图渲染时写数据。
- 从 `status: active` 的 Task 中读取已录入、未完成、非暂停且到达 `resume` 的 Todo；不直接复制昨天的未勾选，也不把所有活跃 Task 或月度 Todo 自动排入今天。
- 生成普通 Markdown occurrence 与精确回链，已有同一锚点（包括今天已完成的）跳过；原文完全一致且已有同一 Task 归属的旧手写项也不重复复制。不同文字且无锚点不做模糊合并，需复盘时关联。
- 沿用最近 45 篇 Daily 中该 Task 最后的高低优先级与 WORK/LIFE 位置，仅把历史用于位置偏好；找不到时按 Task.priority，normal/low 放低优先级，默认 WORK。用户当天可以自由调整，不回写实体分类字段。
- 自动续入只写今天的 Daily；不复制 Task 的过程笔记。生成后再勾选/删除当天切片，不自动改写 Task 原清单。
- 若先建 Daily 后补昨晚 Review，或当天新增了待办，运行命令 **Vault Daily Todos: 续入今天尚未列出的 Task Todo**；只补缺项，不重置已勾选内容。过去/已关闭页面即使手动执行也不写入。
- 插件不可用时，Agent 执行只读 `node .agents/skills/daily/scripts/task-todo.mjs --file <今日Daily绝对路径>` 查看建议正文，检查后应用差异；脚本本身不写文件。历史复盘不得运行生成逻辑来补造当天计划。
- 格式缺失、重复锚点或目标结构不完整时原子拒绝整次续入并提示；不悄悄丢项。多设备同步仍建议只在一个主设备创建/编辑同一 Daily；本地原子写入不是 OneDrive 分布式锁。
- 插件仅桌面运行、不联网、不读 Raw、不改 DIDA、不修改 `.obsidian/workspace*.json`。停用插件不会丢失任何 Markdown 事实；其源代码进入 Git，启用配置仍由 OneDrive 同步。

## 统计

按 `Task 路径 + step ID` 聚合事项，以 Todo 原条目的完成日期判断完成；过程查看该 Todo 的日期笔记及来源 Daily。一个事项多日出现不计为多个新任务。独立小事仍在月度 Todo，不与 Task 明细混算；DIDA 工时仍归属 Task，不推断明细工时。

## 与关注组的关系

Task Group 只影响任务池展示，不参与本工作流的筛选条件。未分组任务、关闭组内任务仍按原 Task 状态和明细调度规则续入 Daily；关闭组不暂停任务。
