# Todo Log

Todo Log 是按记录月份分片的小任务待办池，统一保存今天做或以后做、无需建立 Task Entity 的一次性事项。每个事项只是一行 Markdown Checkbox，不建立独立页面或 Task ID。

总览称“小任务待办池”，Daily 中简写为“小任务”；内部路径 `workspace/todos/`、`type: todo-log` 与 block ID 不变。未完成的小事留在同一清单，今天做的事项也只保留唯一原条目，不复制 Checkbox。

## 路径

```text
workspace/todos/{YYYY}/{YYYY-MM}.md
```

月份表示事项被收进小任务待办池的月份，不是强制完成月份。跨月未完成的事项保留在原文件，由聚合视图继续显示，不机械搬运或复制到新月份。

## Properties

```yaml
---
type: todo-log
period: YYYY-MM
created: YYYY-MM-DD
updated: YYYY-MM-DD
---
```

## 条目格式

```markdown
## WORK

- [ ] 一条常规任务 ➕ 2026-09-18 ^todo-20260918-01
- [ ] 今天必须完成的事项 ➕ 2026-10-03 📅 2026-10-03 ^todo-20261003-01

## LIFE

- [x] 已经完成的事项 ➕ 2026-09-18 ✅ 2026-09-20 ^todo-20260918-02
```

- Checkbox 原行保存当前状态；`➕ YYYY-MM-DD` 为该事项录入日期，`✅ YYYY-MM-DD` 为真实完成日期。日期不可用月文件创建时间代替。
- 取消用 `[-]`，升级为 Task 用 `[>]` 并链接实体；两者均记录 `[closed:: YYYY-MM-DD]`。结束后保留原条目。
- 小任务待办池提供“添加”输入、完成安排选择和 Checkbox：默认“常规任务”，选“今日必做”时写入 Shanghai 当天的 `📅 YYYY-MM-DD`；添加自动记录录入日期与局部 block ID。勾选原子更新原行并写入完成日期，允许撤销当天误勾选。历史页只读。
- 手工添加/编辑月文件时也需填写日期。缺失或矛盾日期显示为“日期待补充”，不能据当前状态伪造历史。Agent 在复盘时根据用户报告或原 Daily 的证据补齐。
- block ID 只是原行锚点，不是 Task Entity ID，也不要求独立页面。取消后重新提出、或跨日重新打开已完成事项，作为新 Todo 录入并链接旧条目，保留原来的时间线。
- WORK / LIFE 只是人工阅读分组，不增加实体字段。普通事项不要求标签、优先级或截止日期；“常规任务”不是低优先级，只表示当前不必当天完成。

## 完成安排与改期

- `📅 YYYY-MM-DD` 保存具体应完成日期，不保存会随日历漂移的 today 布尔值。无日期的已有任务默认常规任务，不批量补日期或猜测承诺。
- 视图按查看日期分为“今日必做”（到期日等于本日）、“逾期”（早于本日）和“常规任务”（未设日期或日期尚未到）。未来已安排的常规任务显示应完成日期，到期后自动进入今日必做；逾期不自动滚到今天。
- 每条显示 `➕` 录入日期，跨年显示完整年份；它是进入清单的日期，不能冒充精确到分钟的创建时间。
- 未完成原条目提供“安排 / 改期”，可设为今日必做、指定今天或以后的日期、转回常规任务。每次修改复用同一 ID、创建日期与 Checkbox 状态，不复制任务。
- 为保护缺快照时的历史回看，改期入口在原行维护 `[due_history:: 2026-09-18=none; 2026-10-03=2026-10-03; 2026-10-04=2026-10-06]`。每项表示该日最终安排，`none` 表示不设日期；首项记录录入日的初始安排，同一天多次调整保留最终值，最后一项须与当前 `📅` 一致。已有快照始终优先，不因同日改期刷新。
- 新建时可直接写 `📅`；已有任务改期优先使用视图或 Daily Skill 的 `todo-schedule.mjs`，避免只改当前日期而丢失先前安排。手动维护历史需保留日期顺序和真实发生日，不反向改写过去。安排字段损坏或不一致时显示待补充并阻止快照，不降级为常规任务。

## 与 Daily / Task 的边界

- 一次性事项统一写入 Todo Log，在今日 Daily 的“小任务”或待办总览直接添加、勾选；不再维护另一份今日安排。
- 今天没做完仍留在原条目，不需要逐日搬运或额外交接；今日必做和逾期项需在复盘时明确处理。
- 工作本身需要多次推进、独立上下文、Weekly 聚合或稳定外部映射：建立 Task Entity。
- “等待了很多天”本身不构成 Task Entity；只有事项的执行与上下文真正跨日时才升级。

旧 Daily 的一次性事项交接到 Todo 时，在 Todo 原行补 block ID，并把 Daily 原 Checkbox 收口为 `[>] ... → [[workspace/todos/YYYY/YYYY-MM#^todo-YYYYMMDD-NN|小任务待办池]]`。原 Daily 保存当天的交接事实，Todo 原行保存以后是否完成；不批量迁移历史事项。

它不承接某个 Task 内部的未完成步骤；这些步骤留在该 Task 的 `## Todo`，两者独立。

## 每日回看与快照

- Daily 的 `小任务` 直接展开同一份清单。常规任务不要求清空；仍有今日必做或逾期事项时，`daily-review-check.mjs` 返回 `smallTaskIssues`、`closeable: false` 和退出码 2。根据用户决定完成、取消、转 Task，或明确改期 / 转回常规任务后才能关闭；Agent 不为通过校验自行改期。旧候选池不作为第二份 occurrence 重复计数。
- Daily 小任务待办池以 `Daily.date` 为准：录入不晚于本日且结束晚于本日/未结束的进入当天待办，再按当时安排分组；本日完成、取消或转 Task 的单独显示。未来新建事项不进入旧 Daily。
- 没有快照时，视图明确标为按日期回看；它能还原状态，但正文来自现存原条目。缺日期项单独提示，不自动认定为当天待办。
- `/daily-review` 保存 `workspace/daily/_meta/todos/{YYYY}/{YYYY-MM}/{YYYY-MM-DD}.todos.md`，冻结当天仍待办、当日完成和当日取消/转 Task 的文字、来源、录入日期及完成安排；使用普通列表，不能勾选历史。新快照为 version 2，条目包含 `created` 与当日 `due`；version 1 继续原样读取和显示“仍待办”，不猜测当时的截止日期、不自动升级。
- 快照优先于动态日期回看。再次 Review 默认沿用已保存的快照，仅在用户明确纠正该日记录时重新生成；事后生成标记为 reconstructed，不冒充当日保存。
- 今日开放 Daily 和待办总览直接操作同一原条目；若需补充当天经过，在小零碎中链接原条目即可。小任务的每日状态由快照保存，数量独立展示，不重复算入 Daily occurrence 数量。
- 今日开放 Daily 的复盘检查读取当前原条目，不能借旧快照绕过后来添加的必做项；历史或已关闭页面优先检查已保存快照，缺快照才按原行日期与安排历史重建。不重开历史 Daily，也不推断旧快照没有记录的承诺。
