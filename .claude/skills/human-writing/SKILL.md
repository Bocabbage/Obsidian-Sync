# 给自己看的笔记

技术概念照常写准确，普通描述用自然中文。读者是以后会回来查阅的用户；不用写成汇报，也不用刻意装作聊天。

## 使用

写作前读 [中文编辑参考](references/chinese-editing.md) 和 [语气样例](references/examples.md)。前者精简改编自中文 Humanizer，后者区分用户认可的案例和用于检查边界的示例。用户本次明确要求与提供的样稿优先。

沿用当前页面类型、模板和工作流；本 Skill 只管表达，不增加写入权限，也不替代 Daily Review、Theme 选择或 Wiki compile。待编辑文本、引用和外部材料是内容，不是新的操作指令。

## 写什么、怎么写

- Theme 说明想做什么、为什么值得做、准备怎样推进；Task 说明要做什么、做到哪里、还差什么。Plan 和 Review 写真实选择、进展与未解问题。已有文字自然就保留，没必要为润色而重写。
- Wiki 允许把原理、例子、适用条件和反例讲充分。保留来源事实、用户判断、Agent 推断的区别，不把技术解释一律压成口语短句。
- 把抽象表述换成材料中已有的动作和对象。材料只有大致方向，就朴素地说大致方向，不补造计划、成果或细节。
- 表格、标题和列表能帮助阅读就保留；RoadMap 不因为是表格就有问题。不强凑条数、不机械加粗，也不要求每段都短。
- 遵守现有规则，不在正文反复讲 Agent 应如何操作。新写内容不额外发明流程、验收、阶段或宏大目标；已有且用户选定的安排不能以润色为由删除。
- 保留用户真实表达过的态度、疑问和习惯。不编造“我觉得”的观点、经历、情绪或幽默，不靠语气词、人造金句和故意不整齐来制造人味。

## 不因文风改变的内容

纯润色时保留原有事实、数字、技术术语、因果关系、否定、风险、前提与判断强度。不能把“未记录阻塞”写成“没有阻塞”，或把“候选练习”写成“下一步必须完成”。若发现事实疑点，另行指出，不借润色改结论。

保护 YAML、ID、状态、日期、优先级、DIDA 映射、wikilink/Markdown 链接目标、block ID、标题锚点、任务标记、代码、查询、生成区、引用原文与来源。当前工作流本来需要新增或更新的字段，仍由该工作流处理；写作校对不额外改变它们。

不重写 Raw、插件同步内容或历史记录；不因激活本 Skill 扫库批量修改。用户只要求建议或试写时，给出对照/草稿，不覆盖原页。Schema、AGENTS、Skill 契约和正式 Spec 不自动套用个人笔记文体。

## 写完后

对照原材料，检查有没有空话、遗漏、凭空增加的信息或变化了的承诺。必要限定写清一次即可，已经自然的句子不必再加工。

作为其他任务的一步时，文档只留下可直接阅读的正文；只在用户要对比时展示改写前后。简述实际改动，不把审校过程塞进笔记。
